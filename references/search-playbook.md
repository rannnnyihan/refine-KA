# 分层采证手册

## 执行约定

本手册描述的是执行智能体要亲自完成的联网研究。生成计划、建立空JSON、运行评分器或发现工作量较大都不代表研究已执行。输入200家时必须逐家至少完成一次“企业全称+地区/行业”的定位检索，并实际阅读找到的官网、年报、政府公示或权威第三方页面；保存真实URL、摘录、日期和查询日志后才计为已粗采。

按批次推进并把结果持续写入同一运行目录。一个批次完成后直接开始下一批；不要在批次之间要求用户再次确认，不要因上下文压缩或一次回复边界重新初始化。只有系统性联网阻塞或用户暂停时才停止。

## 第一阶段：覆盖全部名单
先按segment建立共享赛道增长依据；获取国家资质/荣誉/绿色认证/政策名单批量比对。每家优先定位最新年报和官网，保存报告锚点及页码，一次提取营收、CAPEX、研发费用、出口或境外收入（口径须标明）、研发强度。顺手保存其他指标证据但不单独展开事件检索。

第一阶段必须覆盖输入名单全部企业。Excel中已有的注册资本排序、平台行业标签、企业简介或AI摘要不得代替联网粗采，也不得直接决定候选池。每家至少保留主体定位结果、官网/一手来源是否找到、实际读取页面、可用粗采维度和缺失原因。

上市主体看公司/交易所原始年报，非上市主体查官网及上市股东年报子公司或合营联营披露；股东合并数据不可冒充子公司数据。CAPEX现金流不等于任意投资金额。英文披露主体用英文名称检索。可用现有网页/PDF能力，不依赖专有付费平台。

粗排10项可用一批来源覆盖多家、多指标、多期。计划不是执行日志。每次真实搜索/阅读保存查询或所读URL、时间、实际结果、证据摘录与位置。公司官网S1，政府原始公示S2，不能把政府归成S1。

## 第二阶段：精采候选池（约40家）
先查看s1-gap-plan.md。**年报/官网优先、一次铺满全部23维**：先批量读最新年报与官网，一次抽取营收、CAPEX、研发、出口/境外收入、研发强度、前五大客户、定增/发债等可证维度，不要逐维单独搜，也不要只做10项粗排指标就停。其余需单独检索的维度（客户预算、市占、海外投资、并购、招聘、关键岗位、组织扩张、商业化等）再从已读材料与按方法文档的时间×来源顺序补缺；历史已有证据也要检查当年缺口。

优先处理可批量补齐的缺口，再处理候选池中高权重的单家缺口。招聘数量不能当员工增长，宣传性“领先”不能证明排名，专利数量不能直接证明重大技术突破，研发人员比例不能替代费用率。替代信号需支持同一评分命题；证据不足则保留待查或未证实。

### 信息要"找全"并"并入"
- **找全**：对当前Top30（及第25–35名临界）逐家建"23维 × 已定档/缺口"清单，优先把可证实维度补到证据定档率 **≥80%**；剩余缺口多为CAPEX、招聘、绿色认证等非强制披露项，以及未上市子公司被并表导致的结构性不可得，保留折算/缺口即可，不臆造。
- **并入**：补证是回填**已证实期（verified）的2025/2024数据**，2026YTD保持空=当年确实未发布，不为填满伪造2026。补证来源分级 S1公司披露>S2政府/监管>S3行业/第三方>S4聚合线索（仅作线索，usable=false，不得直接定档）；聚合检索（东方财富/格隆汇/招聘聚合）误标S1–S3会触发验收报"S4仅作线索，不允许直接定档"。改完用备份恢复后重放patch，重跑 `ingest_raw → score → audit → gen`，**不手改HTML数字**。
- 证据率 = `score_companies.py` 输出的 `evidence_cells / (23 × 主榜数)`。低于50%时排名主要反映"公开披露程度"而非真实实力，必须在页面与答复中说明。

## 停止条件
找到同主体、同事实期间、足够定档且没有未解决冲突的来源即可停止该项，不必凑三轮或四级日志。查无证据时实际扩展入口，满足search-acceptance后才标saturated。访问受阻标blocked，不算查尽。S4发现后追溯原文；不得将媒体线索直接提升为S1。

不承诺固定耗时或预筛相关性。输出保留低覆盖及临界企业复核记录。默认顺序执行，批次5–8家仅用于组织数据；工具允许且另有授权时可并行，但不将子代理视作必需依赖。

## 2.2 执行重点
初筛给每家相近的官网浏览深度，同时捕捉23维内业务信号，不能只读年报。两通道由prescreen.py分配精采名额，过程不进UI。
精采约40家形成初排后，按top30-quality.json集中补齐当前30家完整信息，兼顾第25–35名附近可能改排名的缺口；每次补证重算并验收新入选者。只做有新入口或材料的补查，不循环重复无效查询，公开信息不足保留真实草稿。
